# 2026-11-04 - v0.4: A/B variants through the CLI

## Why
`foxreach-cli` 0.6.0 (PyPI, 2026-11-04) adds `foxreach sequences variants list / add / update /
delete / stats` over the v1 variant routes (`/campaigns/{id}/sequences/{sid}/variants`,
`.../variant-stats`), which production serves. The "API reads variants but cannot create them"
gap from the v0.3 refresh is closed.

## What changed
- cold-send: creates variant A (control copy) and variant B with `sequences variants add`, checks
  them with `variants list`, records `sequenceId` and both variant IDs in the protocol. A step with
  variants always sends one of them (the step's own copy is unused), which is why A is created too.
  The old check read `hasVariants` and `variants` from `sequences list --json`; the CLI's
  `sequences list` output has neither field, so it could not have matched.
- cold-learn: promote or end a test with `variants update --weight` / `variants delete` (deleting
  one of two deletes both and the step reverts to its own copy) instead of app steps; missing IDs
  come from `variants list`. Guard breach: end the test the same way.
- cold-experiment: protocol gains `sequenceId`; prose and constraints point at the variants commands.
- cold-draft: no more "created in the app".
- /cold init: warns when `foxreach --version` is below 0.6.0.
- README, CLAUDE.md, site (A/B variants card, hero badge v0.4): same correction.
- Version 0.4.0 in plugin.json and marketplace.json.

## Verified
- Every command line in the changed skills parsed by the published CLI 0.6.0 (click, callbacks
  stubbed); the add / list / update / delete lines also ran end to end against a local fake of the
  v1 routes and sent the bodies the backend models accept (`label, subject, body, weight, sendAsHtml`).
- `scripts/check.sh` passes; `claude plugin validate` passes for the plugin and the marketplace;
  `cd site && npx next build` passes.

## Not verified
- Not run against production (no live campaign was touched).
